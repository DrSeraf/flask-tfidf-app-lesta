## Описание проекта

Это веб-приложение для анализа текстовых файлов с помощью алгоритма TF-IDF (Term Frequency-Inverse Document Frequency). Приложение позволяет загружать текстовые файлы, анализировать их и визуализировать результаты в виде таблиц, облаков слов и графиков. Пользователи могут создавать аккаунты, управлять документами и коллекциями, а также получать статистику по TF-IDF и кодирование текста с помощью алгоритма Хаффмана.

## ✨ Особенности

- Анализ текста с помощью алгоритма TF-IDF
- Удаление стоп-слов (русский язык)
- Предобработка текста (очистка от пунктуации, приведение к нижнему регистру)
- Сортировка результатов по убыванию IDF
- Постраничный вывод результатов
- Визуализация:
  - Облако слов
  - График топ-10 слов по TF
- Скачивание результатов в формате CSV
- Фильтрация результатов прямо в браузере
- Ограничение размера загружаемого файла (2 МБ)
- Автоматическое создание папки для загрузок
- Валидация формата файла (только .txt)
- Аутентификация и авторизация пользователей
- Управление коллекциями документов
- Кодирование документов с помощью алгоритма Хаффмана
- Интеграция с SQLite для хранения данных пользователей и документов
- Swagger-документация API

## Запуск приложения

### Локальный запуск

1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Запустите приложение:
   ```bash
   python app.py
   ```
3. Приложение будет доступно по адресу: [http://localhost:5005](http://localhost:5005)
4. Swagger-документация доступна по адресу: [http://localhost:5005/apidocs/](http://localhost:5005/apidocs/)

### Запуск в Docker

1. Соберите образ:
   ```bash
   docker build -t tfidf-analyzer .
   ```
2. Запустите контейнер:
   ```bash
   docker run -p 5005:5005 -v $(pwd)/Uploads:/app/Uploads tfidf-analyzer
   ```
3. Приложение будет доступно по адресу: [http://localhost:5005](http://localhost:5005)
4. Swagger-документация доступна по адресу: [http://localhost:5005/apidocs/](http://localhost:5005/apidocs/)

## API Endpoints

API документировано с помощью Swagger и доступно по адресу `/apidocs/`. Все эндпойнты, кроме `/register` и `/login`, требуют авторизации через заголовок `x-access-token`.

### Пользователи
- **POST /register** — Регистрация нового пользователя (логин и пароль)
- **POST /login** — Авторизация пользователя, возвращает токен
- **GET /logout** — Завершение сессии пользователя
- **PATCH /user/<user_id>** — Изменение пароля пользователя
- **DELETE /user/<user_id>** — Удаление аккаунта пользователя и всех его данных

### Документы
- **POST /upload** — Загрузка текстового файла
- **GET /documents/** — Получение списка документов пользователя
- **GET /documents/<document_id>** — Получение содержимого документа
- **GET /documents/<document_id>/statistics** — Получение TF-IDF статистики документа
- **GET /documents/<document_id>/huffman** — Получение содержимого документа, закодированного алгоритмом Хаффмана
- **DELETE /documents/<document_id>** — Удаление документа

### Коллекции
- **POST /collections** — Создание новой коллекции
- **GET /collections/** — Получение списка коллекций пользователя
- **GET /collections/<collection_id>** — Получение списка документов в коллекции
- **GET /collections/<collection_id>/statistics** — Получение TF-IDF статистики по коллекции
- **POST /collections/<collection_id>/<document_id>** — Добавление документа в коллекцию
- **DELETE /collections/<collection_id>/<document_id>** — Удаление документа из коллекции

### Служебные
- **GET /status** — Проверка статуса приложения: `{"status": "OK"}`
- **GET /metrics** — Метрики приложения:
  ```json
  {
    "uploaded_files_count": 0,
    "processed_words_total": 0,
    "average_processing_time_ms": 0
  }
  ```
- **GET /version** — Версия приложения: `{"version": "1.2.0"}`

## Структура базы данных

База данных реализована с использованием SQLite и содержит следующие таблицы:

- **User**:
  - `id` (Integer, Primary Key) — Уникальный идентификатор пользователя
  - `username` (String, Unique) — Имя пользователя
  - `password` (String) — Хэш пароля

- **Document**:
  - `id` (String, UUID, Primary Key) — Уникальный идентификатор документа
  - `filename` (String) — Имя файла на диске
  - `user_id` (Integer, Foreign Key) — Идентификатор владельца документа

- **Collection**:
  - `id` (String, UUID, Primary Key) — Уникальный идентификатор коллекции
  - `name` (String) — Название коллекции
  - `user_id` (Integer, Foreign Key) — Идентификатор владельца коллекции

- **CollectionDocument**:
  - `id` (Integer, Primary Key) — Уникальный идентификатор связи
  - `collection_id` (String, Foreign Key) — Идентификатор коллекции
  - `document_id` (String, Foreign Key) — Идентификатор документа

Диаграмма структуры базы данных доступна в файле [database_diagram.png](database_diagram.png).

## Алгоритм Хаффмана

Эндпойнт `/documents/<document_id>/huffman` реализует кодирование содержимого документа с помощью алгоритма Хаффмана. Алгоритм реализован без использования сторонних библиотек.

### Описание реализации
- **Шаг 1**: Построение частотного словаря символов текста (`build_frequency_dict`).
- **Шаг 2**: Создание бинарного дерева Хаффмана (`build_huffman_tree`) с использованием кучи (`heapq`).
- **Шаг 3**: Генерация кодов для каждого символа (`build_codes`).
- **Шаг 4**: Кодирование текста с использованием сгенерированных кодов (`huffman_encode`).
- **Шаг 5**: Возврат закодированного текста, кодов символов и коэффициента сжатия.

### Преимущества
- Эффективное сжатие текста за счёт присвоения коротких кодов часто встречающимся символам.
- Возможность восстановления исходного текста при наличии кодов.

   - Облако слов и график топ-10 по TF.
   - Возможность фильтровать таблицу по слову, TF и IDF.
   - Возможность скачать результаты в формате CSV.

## О TF-IDF

**TF-IDF** (Term Frequency-Inverse Document Frequency) — это статистическая мера, используемая для оценки важности слова в контексте документа или корпуса. Она помогает выделить ключевые слова, которые наиболее важны для конкретного текста, учитывая их частоту и уникальность среди других документов.

**Формула TF-IDF:**
```
TF-IDF = TF * IDF
```
где:
- **TF** (Term Frequency) — частота термина в документе.
- **IDF** (Inverse Document Frequency) — обратная частота документа (логарифм общего числа документов, делённый на количество документов, содержащих термин).
